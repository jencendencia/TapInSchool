# GitHub Release Upload Guide

This guide documents the correct process for uploading the **TapIn School** installer to GitHub releases, avoiding the filename mismatch error.

## The Problem

When electron-builder generates the installer, it creates files with **spaces** in the name:
```
TapIn School Setup 2.0.1.exe
```

But when uploaded to GitHub, spaces are converted to **dots**:
```
TapIn.School.Setup.2.0.1.exe
```

The `latest.yml` file generated by electron-builder references the original filename (with spaces), causing a **404 error** when the auto-updater tries to download the update.

## Step-by-Step Process

### 1. Bump Version

Edit `package.json` **and** `package-lock.json` (root + packages entry) and update the version:
```json
{
  "version": "2.0.1"
}
```

### 2. Build the Installer

```bash
npm run dist
```

This creates files in the `release/` folder (see `electron-builder.yml` → `directories.output`):
- `TapIn School Setup X.X.X.exe`
- `TapIn School Setup X.X.X.exe.blockmap`
- `latest.yml`

### 3. Fix the latest.yml (CRITICAL)

Open `release/latest.yml` and replace **spaces with dots** in the filename:

**Before (wrong):**
```yaml
version: 2.0.1
files:
  - url: TapIn School Setup 2.0.1.exe
    sha512: ...
    size: ...
path: TapIn School Setup 2.0.1.exe
sha512: ...
releaseDate: '...'
```

**After (correct):**
```yaml
version: 2.0.1
files:
  - url: TapIn.School.Setup.2.0.1.exe
    sha512: ...
    size: ...
path: TapIn.School.Setup.2.0.1.exe
sha512: ...
releaseDate: '...'
```

### 4. Delete Old Release (only if re-uploading the same version)

If you are re-uploading a version that already has a release (e.g. fixing a broken upload), delete it first. For a **new** version there is nothing to delete:

```bash
gh release delete v2.0.1 --repo jencendencia/TapInSchool --yes
```

### 5. Create New Release and Upload

```bash
gh release create v2.0.1 \
  "release/TapIn School Setup 2.0.1.exe" \
  "release/TapIn School Setup 2.0.1.exe.blockmap" \
  "release/latest.yml" \
  --repo jencendencia/TapInSchool \
  --title "v2.0.1" \
  --notes "Release notes here"
```

### 6. Verify the Upload

```bash
gh release view v2.0.1 --repo jencendencia/TapInSchool
```

Check that:
- Asset names use **dots** (not spaces)
- `latest.yml` references the correct filename with dots

### 7. Verify latest.yml Content

```bash
# Download and check the latest.yml from the release
# It should reference TapIn.School.Setup.X.X.X.exe
```

## Quick Reference Checklist

- [ ] Version bumped in `package.json` and `package-lock.json`
- [ ] Ran `npm run dist`
- [ ] Fixed `latest.yml` - replaced spaces with dots in filename
- [ ] Deleted old release (only if re-uploading the same version)
- [ ] Created new release with all 3 files:
  - `.exe` installer
  - `.exe.blockmap` file
  - `latest.yml` (with dots in filename)
- [ ] Verified asset names use dots
- [ ] Verified `latest.yml` content matches asset names

## Token Management

**For public repos:** No token needed for auto-updater.

**For private repos:** Pass token via environment variable when building:
```bash
export GH_TOKEN="ghp_your_token_here"
npm run dist
```

**Never commit tokens to source code** - GitHub's secret scanning will block the push.

## Common Errors

| Error | Cause | Fix |
|-------|-------|-----|
| 404 when downloading update | `latest.yml` filename doesn't match asset | Fix `latest.yml` to use dots |
| Push rejected (secret scanning) | Token in committed code | Remove token, use env variable |
| Release not found | Old release not deleted | Delete old release first |
